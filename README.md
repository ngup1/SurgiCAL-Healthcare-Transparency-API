# SurgiCAL API

A FastAPI service for comparing **surgical procedure prices, hospital and surgeon quality, and medical-device safety** in California. It runs on PostgreSQL with PostGIS for distance search and pg_trgm for fuzzy text search.

> **All data in this repository is fictional.** Hospitals, providers, manufacturers, devices, prices and quality scores are generated by `api/seed/generate.py`. CPT code numbers are real; their descriptions are paraphrased.

**Live demo:** https://surgical-api.onrender.com/docs. It runs on Render's free tier, so the first request after a period of inactivity can take up to a minute while the service wakes up.

[![API CI](https://github.com/ngup1/SurgiCAL-Healthcare-Transparency-API/actions/workflows/api-ci.yml/badge.svg)](https://github.com/ngup1/SurgiCAL-Healthcare-Transparency-API/actions/workflows/api-ci.yml)

## Quick start

Requires Docker.

```bash
make up          # builds and starts Postgres/PostGIS (seeded) + the API
open http://localhost:8000/docs
```

Swagger UI at `/docs` lets you try every endpoint. Some values to try:

| Try | Example |
|---|---|
| Hospital | `GET /hospitals/050801` |
| Knee replacement prices, cheapest first | `GET /prices?cpt=27447` |
| Search across procedures, providers, hospitals and devices | `GET /search?q=knee` |
| Device recalls and adverse events | `GET /devices/68670191-dbe2-5dbd-a693-5f7118cab2c2` |

Stop with `make down`. Reset the database to the seed data with `make db-reset`.

## Endpoints

| Area | Endpoints |
|---|---|
| Hospitals | `GET /hospitals`, `/hospitals/{ccn}`, `/hospitals/{ccn}/providers` |
| Providers | `GET /providers`, `/providers/{npi}` |
| Prices | `GET /prices`, `/prices/compare` |
| Devices | `GET /devices`, `/devices/by-procedure/{cpt}`, `/devices/{id}`, `/devices/{id}/recalls`, `/devices/{id}/adverse-events` |
| Search | `GET /search` |
| Places | `GET /places` (valid California cities, counties, and ZIP codes) |
| Health | `GET /health` |

**Location filters** (on `/hospitals`, `/providers`, `/prices`): `city`, `county`, or `zip`, plus `radius_miles` with a city or ZIP to include nearby places, sorted nearest first. Coverage is California only, and other locations return a `422` with a specific `code`:

| Request | Result |
|---|---|
| `?county=Los Angeles` | Hospitals in every city in the county |
| `?city=Pasadena&radius_miles=15` | Within 15 miles of Pasadena, nearest first |
| `?state=NV` or `?zip=89502` | `422 location_outside_coverage` |
| `?city=Pasedena` | `422 location_not_found` with `"suggestions": ["Pasadena"]` |

List endpoints take `limit`/`offset` and return the total match count in an `X-Total-Count` header. Unknown IDs return `404`, including on sub-resources such as `/hospitals/{ccn}/providers`.

Each client can make 120 requests a minute (30 to `/search`); past that the API returns `429` with a `Retry-After` header. Limits are per worker process and set with `RATE_LIMIT_PER_MINUTE`, `RATE_LIMIT_SEARCH_PER_MINUTE` and `RATE_LIMIT_ENABLED`. Behind a proxy, set `RATE_LIMIT_CLIENT_IP_HEADER` to a header the proxy sets and clients can't forge (e.g. `True-Client-IP`); otherwise clients are told apart by connection address.

Malformed input returns `422` with the bad field named:

```json
{
  "code": "validation_error",
  "detail": "Invalid value for 'npi': Must be a 10-digit National Provider Identifier, e.g. 1572628497",
  "errors": [{ "field": "npi", "location": "path", "message": "...", "input": "123" }]
}
```

[`api/API_GUIDE.md`](api/API_GUIDE.md) explains the API's design and how it uses FastAPI.

## Development

```bash
make install-dev   # virtualenv + API, test and lint dependencies
make db-up         # database only, on localhost:5433
cp api/.env.example api/.env
make run-api       # API with auto-reload on localhost:8000

make test          # pytest against the seeded database
make lint          # ruff check + format check (make format to fix)
make seed-data     # regenerate the mock data, then make db-reset
```

## CI/CD

[`.github/workflows/api-ci.yml`](.github/workflows/api-ci.yml):

- **Every push and pull request:** ruff lint, then the test suite against a seeded PostGIS database, then the production image is built and smoke-tested.
- **Merges to `main`:** the image is published to `ghcr.io/ngup1/surgical-api` for amd64 and arm64, tagged `sha-<commit>` and `latest`.

## Project layout

```
api/
  src/                   the app, organized by domain (fastapi-best-practices)
    main.py              app setup: lifespan (DB pool), routers, error handlers
    config.py            settings from environment variables
    database.py          async connection pool (psycopg 3)
    hospitals/ providers/ prices/ devices/ search/ locations/ health/
                         each: router.py (HTTP), service.py (SQL), schemas.py
                         (response models), dependencies.py, exceptions.py
  tests/                 pytest suite
  seed/                  mock-data generator, JSON fixtures, seed.sql
  db/Dockerfile          PostGIS image with migrations + seed data
  Dockerfile             production API image
migrations/              database schema (SQL)
etl/                     pipeline that loads real CMS, FDA and hospital price data (not needed for the mock setup)
  run_pipeline.py        runs the steps in dependency order and records each run in etl_runs
  extract/               one module per source
  reference/             hand-kept inputs: hospital websites, payer aliases, procedure-to-device map
  checks.py              row-count and storage checks that gate promoting a refresh
  tests/                 pytest suite on saved copies of real API responses
```

## Loading real data (ETL)

The mock data is enough to run and test the API. `etl/` replaces it with public data:

| Step | Source | Fills |
|---|---|---|
| `places` | Census Gazetteer | `ca_places` (cities, counties, ZIP centre points) |
| `hospitals`, `hospital_quality` | CMS Hospital Compare | `hospitals`, `hospital_quality` |
| `cpt_codes` | CMS Physician Fee Schedule | `cpt_codes` |
| `providers`, `utilization` | NPPES registry, Medicare utilization | `providers`, `provider_metrics`, `provider_procedure_volumes` |
| `fda_devices`, `fda_recalls`, `fda_maude` | openFDA | `devices`, `device_recalls`, `device_adverse_events` |
| `device_procedures` | `etl/reference/procedure_product_codes.csv` | `device_procedure_map` |
| `mrf_links`, `mrf_prices` | each hospital's `cms-hpt.txt` and price file | `hospital_mrf_links`, `prices` |

Load into a database made for it, never the one the API is serving. Locally:

```bash
make install db-up
docker compose exec db psql -U surgical -d surgical -c "CREATE DATABASE surgical_etl"
export DATABASE_URL="postgresql://surgical:surgical@localhost:5433/surgical_etl?sslmode=disable"
make etl-migrate                      # schema only, no mock data
make run-etl ARGS="--mrf-limit 10"    # every step; prices for 10 hospitals
make etl-check                        # row counts and database size
```

`make run-etl STEPS="hospitals hospital_quality"` runs chosen steps; `python -m etl.run_pipeline --list` shows them all
and what each needs. A step that loads nothing counts as failed, and steps that depend on it don't run.
Settings are in [`etl/.env.example`](etl/.env.example). For Neon, set `DATABASE_URL` to the direct (non-pooled)
endpoint of a branch.

The [ETL refresh workflow](.github/workflows/etl-refresh.yml) does this on a schedule: it loads into a new Neon
branch, runs the checks against production, and only then swaps the branch in. Its header lists the secrets and
variables it needs; without them it skips.

```bash
make test-etl    # needs `make db-up` for the database tests
make lint-etl
```
